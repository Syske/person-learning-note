# 钉钉投屏修复记录（X11 下可用）

> 归档时间：2026-09-21
> 结论：**钉钉 8.2.8 在 X11 会话下投屏正常可用**（此前"X11 也不可用"的结论是误判，真凶是缺库）
> 环境：Arch / KDE Plasma X11 / dingtalk-bin 8.2.8.260904001

---

## 现象

钉钉发起会议 → 点共享屏幕 → 无反应（投屏页面不弹出）。

## 根因链（两层，缺一不可）

### 第①层：投屏库缺系统依赖 libQt5X11Extras

- `libscreencast.so`（钉钉投屏库）动态依赖 **`libQt5X11Extras.so.5`**
- 系统未装（Arch 清理时被卸/初始没有）→ 投屏库加载失败
- 检查：`ldd /opt/dingtalk/release/libscreencast.so | grep 'not found'`

**修复**：
```bash
sudo pacman -S qt5-x11extras
```

### 第②层：libdt_web_view.so 的 RUNPATH 是构建机路径

- 投屏流程加载 `libdt_web_view.so`（在 `plugins/dtwebview/` 下），它依赖 `libcef.so`（CEF 内核，同目录）
- 但它的 RUNPATH 写死腾讯 Jenkins 构建机路径（`/mnt/diskdata/jenkins/...`）→ 本机找不到 libcef.so
- 报错：`yanghang get libdt_web_view.so fail, dlerror=libcef.so: cannot open shared object file`
- 手动复现：`cd /opt/dingtalk/release && ./tblive --btype=screencast --tcp-port=2965 --locale=zh-CN`

**修复**：钉钉启动脚本加 LD_LIBRARY_PATH（指向 dtwebview 目录）：
```bash
# /usr/bin/dingtalk 中加一行(备份: /usr/bin/dingtalk.bak):
export LD_LIBRARY_PATH=/opt/dingtalk/release/plugins/dtwebview${LD_LIBRARY_PATH:+:$LD_LIBRARY_PATH}
```

## 验证

```bash
# 手动跑投屏进程, 看到以下输出即链路通:
cd /opt/dingtalk/release
LD_LIBRARY_PATH=/opt/dingtalk/release/plugins/dtwebview ./tblive --btype=screencast --tcp-port=2966 --locale=zh-CN
# 关键输出: "yanghang get libdt_web_view.so success" + "DtWebviewBrowserStartup enter"
```

## 注意事项

1. **升级 dingtalk-bin 会覆盖 /usr/bin/dingtalk** → 重新加 LD_LIBRARY_PATH（`dingtalk.bak` 是备份，升级后 diff 参考）
2. `qt5-x11extras` 是 Qt5 兼容库，官方仓库仍维护，保留即可
3. 会话要求：**X11**（`echo $XDG_SESSION_TYPE` = x11）。Wayland 下待测（可能同样可用，待确认）
4. 之前安装的投屏 hook（dingtalk-wayland-screenshare-git）已卸载，不再需要

## 已知问题：关闭投屏页面时 service crash

- **现象**：投屏共享正常，但**关闭投屏窗口时**弹 "service crash" 提示
- **根因**：钉钉 8.2.8 自身 bug——`libscreencast.so` 的 Qt 主窗口析构时堆损坏/双重释放触发 glibc abort（coredump 调用栈：`qui::MainWindow::~MainWindow` → `QObjectPrivate::deleteChildren` → abort）
- **影响**：仅投屏子进程 tblive 崩溃，**钉钉主程序不受影响**；无法修复（等腾讯更新）
- **缓解**：结束投屏优先用会议内「停止共享」按钮；弹提示直接关掉即可

## 经验

- 投屏类问题别急着归因"架构不支持"——**先查依赖链**（ldd/手动跑二进制抓真实报错）
- 钉钉投屏进程是 `tblive --btype=screencast`，日志在 `~/.config/DingTalk/log/dingtalk_YYYY_MM_DD.log`
- 腾讯的 RUNPATH 写死构建机路径是常见坑，LD_LIBRARY_PATH 是通用解法
